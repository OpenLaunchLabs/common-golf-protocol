# C reference implementation

This library runs on POSIX hosts without ESP-IDF and supplies the same protocol
sources to the ESP32 demo. The library owns QUIC/TLS, framing, stream lifecycle,
strict UTF-8 JSON parsing, Ed25519 identities, and connection-local private JSON
channels. Applications provide message callbacks and application behavior; no
synthetic shots are generated by the library.

Draft 1 supports protocol versions 0.1.0 and 0.1.1; draft 2 supports 0.2.0.
Choose `cgp_options.draft` explicitly. The selected ALPN determines behavior;
`info.protocol_version` is informational.

## Standalone build

```sh
python3 implementations/c/tools/fetch_deps.py
cmake -S implementations/c -B implementations/c/build -DCMAKE_BUILD_TYPE=Debug
cmake --build implementations/c/build --parallel
ctest --test-dir implementations/c/build --output-on-failure
```

No global dependency installation is needed for QUIC/TLS/JSON. The fetcher
verifies pinned archive checksums. Discovery uses macOS Bonjour or Linux
`libavahi-compat-libdnssd-dev`; CMake builds `cgp_discovery` when that development
interface exists. Linux also needs the Avahi daemon running. The transport
library can instead consume addresses from an embedded DNS-SD adapter. Standard
applications must use discovery: explicit addresses in `cgp-peer` are only
compatibility-test and diagnostic fixtures.

Embed with `add_subdirectory(implementations/c)` and link
`common_golf::common_golf`, plus `cgp_posix` for the supplied clock, randomness,
and logging implementation. Link `cgp_discovery` for host DNS-SD.
`cmake --install` installs static archives and public headers. The static
archive dependencies are ngtcp2, wolfSSL, cJSON, and the platform math library.

For ASan/UBSan, configure a separate directory with `-DCGP_SANITIZE=ON` and run
CTest there. The native transport regression exchanges standard messages,
connection-local private JSON, and Open Connect request/reply messages over actual
QUIC connections. A queue regression checks that small writes account for both
buffer headers and payload and resume after acknowledgements. The repository's
compatibility runner covers all Python/Rust/C pairings.

## Application API

Include `cgp.h`. Fill `cgp_options` with a device/controller/simulator role,
listener/connector choice, draft, local interface address, identity directory,
and callbacks. Call `cgp_create_options`, advertise `cgp_port` using DNS-SD,
and call `cgp_poll` every 10 ms on one thread. Connectors pass discovered
addresses to `cgp_connect`. Channel ownership follows the application role,
independently of the QUIC listener/connector role.

The `connected` callback publishes channel 0 first using `cgp_publish`; subsequent
messages use their channel numbers. `cgp_publish` returns false for malformed or
forbidden messages, declined channels, or temporary queue/stream capacity limits.
All standard channels 0–8 are implemented. Channel 2 uses a bidirectional stream
opened by a device; simulator replies use `cgp_publish(peer, 2, reply_json)` on
that same stream, without repeating its channel prefix. Send distinct shot
numbers if exercising channel 1 and channel 2 on one connection.

Receive callbacks borrow JSON bytes until they return. Receivers ignore unknown
fields and tolerate cross-stream reordering, including messages arriving before
info. Repository tests check schemas and estimated-field references.
Applications parse the fields they consume.
`cgp_finish_channel` queues FIN after buffered bytes; `cgp_close_channel` resets
and abandons queued bytes. Applications retain shot counters across channel
reopening. Snapshot and patch behavior belong to application state; applications
apply status/state patches and replace shot snapshots according to the RFC.

For private JSON channels, both endpoints call `cgp_bind_private` with a number
of 1000 or above and the agreed identifier. This is local configuration, with
no startup negotiation on the wire. `cgp_private_matches` and
`cgp_channel_contract` inspect the connection-local arrangement. Unknown private
channels are declined. Applications use the authenticated fingerprint and trust
tier to decide which bindings to configure, and should begin private traffic
with a JSON object naming the arrangement as described in the RFC.

The `trust_tier` callback maps an authenticated peer fingerprint to
`internal`, `developer`, or `maker`; absent/unknown identities default to maker.
`accept_channel` enforces application-specific receive permissions. Applications
choose authorized private bindings in the `connected` callback. Fingerprints are
the 32-byte Ed25519 public key in lowercase hex, not a certificate hash.

Host identities persist in the supplied directory as `identity.der` (mode 0600,
directory mode 0700 on creation). A damaged identity fails closed instead of
silently replacing the device's key. A NULL directory creates an ephemeral test
identity. ESP32 uses NVS. Certificates may be self-signed; expiry and CA chains
are intentionally ignored, while TLS CertificateVerify authenticates possession
of the Ed25519 key. The wolfSSL configuration accepts the full TLS ticket nonce
range, including rustls's 32-byte nonces.

## Resource bounds and portability

The default host engine supports 8 simultaneous peers; ESP32 uses
`CONFIG_CGP_MAX_CONNECTIONS`. Each peer supports 32 live streams, 16 private
bindings, and a 262,172-byte queue ceiling for buffer headers plus payload
(allocated on demand; allocator metadata is additional). Standard and private
JSON frames accept up to 65,535 bytes. This implementation exposes framed JSON
private channels; applications needing other private encodings supply their own
transport integration.
Native strict JSON scanning uses an explicit heap stack
for deeply nested unknown content. The transport presently uses IPv4 sockets.

The core has no threads: callbacks, connection operations, and polling must run
on one application thread. Host DNS-SD resolve callbacks currently use the
system resolver for IPv4 addresses. Embedded applications provide their own
clock, random source, log sink, and DNS-SD scheduling; see
`examples/esp32/main/app_main.c`. There is no browser, Windows socket, or
multicast-isolation workaround built into this library.

The reference source is Apache-2.0. **wolfSSL is GPL-3.0-or-later, with a commercial
license alternative**; linking this library does not replace its dependency
license obligations. ngtcp2 and cJSON are MIT licensed. The fetched dependency
source trees contain their license files.


## Complete sample application

The standalone `cgp-demo` target consumes the public library API from
[`examples/c`](../../examples/c/README.md). It demonstrates a device advertising
through DNS-SD and a simulator discovering it, exchanging info, one synthetic
shot, and simulator state using draft 2.
`cgp-peer --fixtures tests/fixtures/conformance.json` is the separate diagnostic
fixture sender used by the cross-language compatibility matrix.
